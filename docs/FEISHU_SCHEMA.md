# 飞书数据结构与视图

## OpenAPI 边界

本项目已通过飞书多维表格 OpenAPI 创建 Bitable、数据表、字段、记录和命名网格视图。公开的服务端能力适合管理这些数据资源；视图内的筛选、排序与展示细节仍在飞书界面配置。参考[飞书多维表格服务端文档](https://open.feishu.cn/document/server-docs/docs/bitable-v1/bitable-overview)。

`所属目标`、`所属里程碑`、`所属任务` 当前使用稳定 ID 的文本字段，避免 OpenAPI 初始化期间产生跨表关联顺序耦合。若以后改为关联字段，应保留 ID 字段作为同步唯一键。

## 01_长期目标（22 字段）

`目标ID`、`目标名称`、`类别`、`目标类型`、`开始日期`、`截止日期`、`目标值`、`当前值`、`单位`、`优先级`、`状态`、`备注`、`剩余天数`、`时间进度`、`实际进度`、`计划值`、`进度差`、`风险状态`、`7日速度`、`14日速度`、`30日速度`、`预计完成日期`。

`当前值`、单位和后十项均由 `sync_progress.py` 从原始打卡重新计算或回写；三个进度字段以 0–100 的百分数存储。`目标值=0` 表示尚未设定量化目标，不产生虚假的风险告警。

2028 届清北学术保研计划只保留 6 个核心 Goal：科研主线、CET-6、专业排名、导师池、408 和 LeetCode。科研/GPA/英语/408 使用投入分钟监控连续性，导师池和 LeetCode 使用 COUNT；真正决定竞争力的论文、模考分数、专业排名和申请节点放在 Milestone 中，不用时长冒充结果。

Seed：LeetCode 220 题、每日英语、408、科研长期投入、课程/GPA 维护。

## 02_阶段里程碑（10 字段）

`里程碑ID`、`所属目标`、`名称`、`截止日期`、`目标值`、`当前值`、`单位`、`状态`、`完成日期`、`备注`。

与 Goal 单位相同的累计型里程碑（例如 LeetCode 题数、导师池人数）由后台自动回算；单位为“节点”“分”“排名%”的结果型里程碑由用户按真实结果手动更新，后台不会覆盖。

Seed 包含三个保研 Deadline 和五个 LeetCode 累计题数节点。

## 03_每日任务（15 字段）

`日期`、`类别`、`任务名称`、`所属目标`、`所属里程碑`、`计划量`、`实际量`、`单位`、`预计时间`、`实际时间`、`优先级`、`状态`、`是否今日`、`备注`、`规则ID`。

`规则ID` 是系统字段，格式为 `日期|类别|rule_id`，用于防止固定任务重复生成。默认生成器不会覆盖已有记录中的手工修改，也不会删除历史任务。

## 04_打卡记录（11 字段）

`打卡时间`、`创建时间`、`日期`、`类别`、`内容`、`所属目标`、`所属任务`、`数量`、`单位`、`投入分钟`、`备注`。

每次打卡新增一行，不覆盖历史。COUNT 目标使用 `数量`，内部单位固定为 `problem`；TIME 目标使用 `投入分钟`，内部单位固定为 `minute`。`创建时间`由飞书自动生成，随后自动回填打卡时间、日期、目标、任务与单位。显示层可把分钟除以 60 展示为小时，但不得把小时写回源数据。

## 05_周复盘（17 字段）

`周次`、`开始日期`、`结束日期`、`计划时间`、`实际时间`、`任务完成率`、`科研时间`、`课程时间`、`英语时间`、`LeetCode题数`、`408时间`、`最大进展`、`最大偏差`、`风险目标`、`本周总结`、`本周问题`、`下周调整`。

## 06_科研项目（9 字段）

`项目名称`、`研究方向`、`当前阶段`、`开始日期`、`目标投稿日期`、`状态`、`本周投入`、`累计投入`、`备注`。

没有预填虚构的论文项目。研究阶段可选值为 Idea、Literature Review、Method、Implementation、Experiments、Writing、Submission、Rebuttal、Revision、Accepted。

## 07_CCF-A投稿路线（6 字段）

- `会议`：每个有效投稿窗口一行
- `CCF方向`：人工智能 / 计算机网络 / 网络与信息安全
- `目标等级`：S（重点冲击）/ A（方向匹配时投稿）
- `预计投稿时间`：明确区分官方日期与“预计/待官方 CFP”
- `当前状态`：未开始 / 调研 / 方法设计 / 实验 / 写作 / 投稿 / Rebuttal / Accepted / Rejected
- `对应科研项目`

本表是科研主线的结果视图，不生成额外日常任务。当前仅跟踪 2026-09 至 2027-06 内的有效窗口，实行“一个核心研究问题 + 一个最匹配的 A 会”；INFOCOM、CCS、NDSS 保留为方向备选，但没有落入当前窗口的明确机会时不激活。

## 已创建视图及人工筛选

在对应命名视图中配置以下条件：

| 表 | 视图 | 筛选与排序 |
|---|---|---|
| 01_长期目标 | 风险目标 | `风险状态` 是 `AT_RISK` 或 `CRITICAL`；按截止日期升序 |
| 02_阶段里程碑 | 里程碑 | `状态` 不是 `已完成`；按截止日期升序 |
| 03_每日任务 | 今日 | `日期` 是今天；按优先级、状态排序 |
| 03_每日任务 | 本周 | `日期` 在本周；按日期、优先级排序 |
| 03_每日任务 | 未完成 | `状态` 是未开始/进行中/部分完成 |
| 03_每日任务 | 科研/课程/英语/LeetCode/408 | `类别` 等于视图名 |
| 05_周复盘 | 周复盘 | 按开始日期降序 |
| 07_CCF-A投稿路线 | 顶会投稿路线 | S 级优先，再按投稿窗口查看；不把所有会议视为必须投稿 |

默认视图可以保留作全量数据入口；API 创建的空白初始“数据表”已在内容全空的前提下删除。
