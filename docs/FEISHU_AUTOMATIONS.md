# 飞书自动化配置

## 支持边界

截至本项目初始化日期，多维表格自动化的触发器、条件分支、消息接收人和动作参数需要在飞书多维表格界面配置；本项目没有可验证的公开服务端接口来可靠创建完整自动化流程，因此未伪造 API 创建结果。飞书官方案例也采用界面配置自动化，参见[多维表格自动化案例](https://open.feishu.cn/community/articles/7291104402634178564?lang=zh-CN)。

进入“保研监督系统”右上角 **自动化 → 新建自动化**，按下列方案建立。具体时刻可按作息调整。

## 1. 每日早晨（建议 08:00）

- 触发：每天定时 08:00。
- 查询：`03_每日任务`，条件为 `日期=今天` 且 `状态` 不是已完成/跳过。
- 汇总：任务列表、`预计时间` 求和、优先级最靠前的一项。
- 动作：向自己发送飞书消息，内容含“今日任务 / 今日计划总时间 / 最高优先级任务”。

若内置消息动作不能直接聚合多行，建立一个“今日”仪表盘组件并使用“发送仪表盘”动作，或把查询结果逐条发送。

### 固定任务生成（已由 Daily Job 接管）

`.github/workflows/feishu-sync.yml` 每小时执行 `daily_job.py`，按 `config/task_rules.json` 幂等生成今天和未来 2 天任务。因此不要再在飞书界面创建相同的任务生成自动化，否则会形成两套计划来源。若同一天同类别只有一个任务，快速打卡会自动关联；若有多个任务，填写可选“内容”为任务名即可精确关联，无需选择 ID。

## 2. 每日晚间（建议 22:30）

- 触发：每天定时 22:30。
- 查询：当天全部任务。
- 条件分支：存在 `状态` 为未开始/进行中/部分完成的记录时才继续。
- 计算：已完成数 ÷ 非跳过任务数；当天打卡的 `投入分钟` 求和。
- 动作：发送“今日完成率 / 未完成任务 / 实际投入”。

## 3. Deadline 提醒

在 `01_长期目标` 和 `02_阶段里程碑` 分别建立四条“到达记录时间”自动化：

- 截止日期前 14 天；
- 截止日期前 7 天；
- 截止日期前 3 天；
- 截止日期前 1 天。

每条均增加条件：`状态 != 已完成`。消息包含目标或里程碑名称、截止日期、当前值/目标值、风险状态。不要用每天扫描替代“到达记录时间”，否则容易重复提醒。

## 4. 风险变化

- 触发：`01_长期目标` 的 `风险状态` 被修改且满足条件。
- 条件：新值是 `AT_RISK` 或 `CRITICAL`。
- 动作：发送目标名称、进度差、剩余天数，并附上“风险目标”视图链接。

使用“记录修改后满足条件”触发器，可避免每天重复发送同一风险；Hourly Daily Job 更新字段时会触发该流程。

## 5. 周日复盘（建议 21:30）

- 触发：每周日 21:30。
- Daily Job 已自动汇总 `03_每日任务` 与 `04_打卡记录`，并按 ISO 周创建或更新 `05_周复盘`。
- 最后向自己发送周复盘记录链接，手工只填写“本周总结、本周问题、下周调整”。

飞书自动化在这里仅负责定时发送周复盘链接，不再负责跨表聚合；不要在飞书自动化中保存 App Secret。
