# Progress Engine

所有算法均为确定性规则，无机器学习，实现在 `src/baoyan_tracker/progress_engine.py`。

## 计算定义

- 时间进度：`(今天 - 开始日) / (截止日 - 开始日)`，限制在 0–100%。
- 计划值：`目标值 × 时间进度`。
- 实际进度：`当前值 / 目标值`，限制在 0–100%。
- 进度差：`实际进度 - 时间进度`，负数表示落后，写入飞书时单位为百分点。
- 速度：最近 N 个自然日投入总量除以 N，支持 7/14/30 日窗口。
- 预计完成日：`今天 + ceil((目标值 - 当前值) / 每日速度)`；速度为零时返回空。
- 连续学习天数：从今天开始向前数；若今天未打卡但昨天打卡，保留截至昨天的 streak。

## 基础风险阈值

| 条件 | 风险等级 |
|---|---|
| 已达到目标值 | COMPLETED |
| 实际进度 ≥ 计划进度 | ON_TRACK |
| 落后不超过 5 个百分点 | SLIGHTLY_BEHIND |
| 落后 5–15 个百分点 | AT_RISK |
| 落后超过 15 个百分点 | CRITICAL |

`目标值=0` 表示目标尚未量化，暂记 ON_TRACK，并给出“目标值尚未设置”的解释，不制造假告警。

## 额外升级规则

- 已过截止日期且未完成：CRITICAL。
- 连续 7 天无投入：至少 SLIGHTLY_BEHIND；连续 14 天：至少 AT_RISK。
- 有计划进度但近期速度为零、无法预计完成：至少 AT_RISK。
- 预计完成日晚于截止日：至少 AT_RISK；预计晚 14 天以上：CRITICAL。
- 最近 7 日速度低于 30 日均速一半：至少 AT_RISK。

每次评估返回等级、计划/实际进度、进度差、预计完成日和原因列表，便于解释与审计。

`scripts/sync_progress.py` 的事实源只有原始打卡。每次运行均重新聚合，而不是在旧汇总上累加：

```text
打卡记录
  → 推断日期/目标/任务/单位
  → 重算每日任务实际量、实际时间、状态
  → 重算长期目标当前值、速度、进度、预计完成日、风险
  → 更新关联里程碑
  → 新建或更新 ISO 周复盘统计
```

因此同一批记录重复同步不会增加数值；修改、删除打卡后也能正确回退。数值比较使用小容差，空值与数值 0 明确区分。
